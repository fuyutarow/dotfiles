# CONFIGURATION CONTRACT — storage-headroom

The configuration system behind `enforce-storage-headroom.ts`. The config says WHAT is guarded;
the hook is the mechanism.

- Consumer: runtime — the `enforce-storage-headroom.ts` PreToolUse hook runs for every tool call from Claude Code and Codex and reads this config for non-allowlisted calls; a human editor authors it
- Authority / writer: the dotfiles owner, by commit to this repo
- Effective configuration: `agents/hooks/storage-headroom.toml`, read through the `~/.claude/hooks` symlink; `STORAGE_HEADROOM_CONFIG` replaces the path for the test suite only
- Source representation: TOML, parsed by Bun's built-in `Bun.TOML.parse` (hooks stay zero-dep)
- Trust regime: human-authored
- Signature / digest input: n/a
- Canonicalization profile: n/a
- Schema / version: `schema = 1`; shared drive thresholds and line math come from `tools/shared/src/storage-headroom.ts`, while the hook validates its remaining fields in `validate()`
- Host recovery floor: `drive.host.stop_gib` is read by `scripts/wsl-capacity-recover.ts`; it must be below `drive.host.deny_gib`. The hook queues `wsl-capacity-recover.service` below the deny line, while its timer covers already-running work. The service first tries `reclaim:host`, `reclaim:builds`, and `reclaim:clean`; below `stop_gib` it stops recognized compute before cleanup, then runs `cargo clean` in the known example-records workspace only after build processes exit. It also samples Windows available RAM and hard page reads, drops guest page cache through Windows `wsl.exe -u root` on severe pressure, and stops compute if pressure remains.
- Guest recovery (GUEST-SELF-HEAL): `[drive.guest]` may declare `recover_gib`/`recover_pct` (a pair, the same min() rule; it sits above deny, and is not `warn_*`, which also refuses launches), `tmp_recover_pct` (tmpfs use of /tmp, the larger of inode and byte use; 95% is the gate's hard-coded deny) and `reclaim_cargo_targets` (cargo workspaces the owner declares reclaimable). On every non-malformed call, before the verdict, the hook measures guest `/` and /tmp and queues `guest-capacity-recover.service` with `systemctl --user --no-block start` once per pressure episode and once more if it escalates to deny; the episode ledger is `~/.local/state/guest-capacity-recover/episode.json` and a quiet drive ends it. The queue is best effort and never changes the verdict. `guest-capacity-recover.timer` (every 5 minutes) covers pressure that builds without tool calls. `scripts/guest-capacity-recover.ts` calls `disk-reclaim run <stage> --yes` for `tmpfs`, `rip-expire`, `clean`, `builds` in that fixed order (disk-reclaim owns every safety check), then `cargo clean` in each declared workspace that has a `Cargo.toml` and no running cargo/rustc; it re-measures before every stage and stops as soon as the pressure is gone. Each stage has its own budget (tmpfs 60 s, rip-expire 120 s, clean 120 s, builds 180 s, so one slow stage cannot starve the rest); a stage that fails or times out is journaled as such and the next stage still runs. Declared cargo workspaces are checked at run time and a missing one is skipped with a `SKIP` line. The unit exits 0 only when the pressure is gone and no stage failed; otherwise it exits 1 (the unit has no `SuccessExitStatus`, so systemd records the failure), including a run that reclaimed nothing while still under pressure. Each action is a stdout line, which the journal keeps. `--dry-run` runs `disk-reclaim plan` per stage and reports the cargo workspaces, and removes nothing. Nothing in this path needs a human or an agent tool permission. `mise run wsl:capacity:enable` enables both timers.
- Drive lines: each `[drive.*]` line is min(`deny_gib` GiB, `deny_pct`% of that drive's size) — and likewise `warn_gib`/`warn_pct`, which come as a pair. Both halves are required, so an absolute size set on a 1 TB disk never judges a 40 GB one alone (2026-10-05: a rented box was denied every launch with its disk 80% empty). `stop_gib` stays absolute: only the host recovery script reads it.
- Tool gating: only disk-writing tools are checked: Bash (by parsed command), `Write`, `Edit`, `MultiEdit`, and `NotebookEdit`. Codex `exec_command`, `shell`, and code-mode `exec` arrive as Bash. Other tools, including `Read`, `Grep`, `Glob`, `SendMessage`, `ListAgents`, `AskUserQuestion`, `TaskStop`, `ToolSearch`, and MCP read tools, pass without a storage measurement. A checked tool is denied below a drive's deny line except the command allowlist. Bash commands are parsed structurally and every command in a chain must be allowlisted. Cleanup exceptions are `disk-reclaim`, `storage-headroom`, `mise run reclaim*`, `m reclaim*`, scoped `cargo clean` (cwd or `--manifest-path` directory must contain `Cargo.toml`), `jj workspace forget`, and `jj abandon`. Worker dispatch and run commands use `agx worker dispatch|run` or `agx-worker dispatch|run`; the worker's declared writes remain individually gated. Read-only Bash exceptions are `df`, `du`, `dust`, `ls`, `cat`, `head`, `tail`, `rr`, `jj st`, `jj log`, and `jj workspace list`.
- Launcher matching: commands in `launcher` are denied at the warn line. Other tool calls are denied only at the deny line. Between the lines, calls pass with `additionalContext` naming the measured free space and `disk-reclaim plan`; above the warn line they pass silently.
- Free-space cache: statfs results are stored under `~/.cache/claude-hooks/storage-headroom` and expire after at most 2 seconds. Artifact-size cache remains governed by `measure.cache_minutes`.
- Cargo target budget: the same target-directory measurement applies to direct Cargo and the `mise run` / `m` build tasks. At 30 GiB it adds cleanup advice; at 80 GiB it denies another build while leaving `cargo clean` and `reclaim:*` callable. The size cache expires after `measure.cache_minutes`.
- Duplicate-key policy: reject — a TOML parse error, reported as "is not valid TOML" in a deny
- Number / Unicode policy: every size and bound is a finite non-negative TOML number (GiB, seconds, minutes); strings are UTF-8 and must be non-empty; launcher commands must match `[A-Za-z0-9._-]+`
- Precedence / merge: one file, no merge and no defaults; an unknown key, wrong type, or missing field makes the whole config invalid, and every error is reported in one deny
- Decision record: none: the effective declaration's writer is the sole authority; the reason for each number is a comment beside it in the TOML
- Deny advice: names each short drive with exact free bytes and deny-line bytes, then lists up to five safe blind-tier reclaim candidates and their cached sizes. The hook reads a capped, one-hour cache and never scans for candidates. The first line gives the single safe action command, `disk-reclaim run --tier blind --yes`. `rip` must not be used to free overlay space.
- Verification command: `bun test agents/hooks/tests/*storage*`
- Positive case: above the warn line, any tool call returns no decision; below the deny line, non-disk-writing tools and allowlisted cleanup/read-only Bash commands return no decision, including scoped `cargo clean` and worker dispatch/run commands
- Negative case: below the deny line, unlisted Bash writes and file-write tools are denied, including writes chained after an allowlisted command; launcher entries are also denied below the warn line.
