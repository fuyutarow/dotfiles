## A. agx：概念の重複と、形だけで眠っている規律
- A1. 作業を指す名前が 4 種類ある（ticket 名、run id、worker 名 agt_x、vendor の session id）。フラグごとに受け付ける名前が違う。prompt-file の作業には ticket がなく、--amend が no ticket home で失敗した。提案：prompt-file も名前のない ticket とし、宛先を ticket の 1 種類にまとめる。
  - ID: `R2610-0A-A1`
  - 状態: in progress — ticket: `agx_one_handle`
  - 原則: 作業の宛先は一つの handle に統一し、起動経路による例外を作らない。
- A2. 行の抽選が気づかれないまま泡沫候補を選んでいた。ε 平滑化（確率の 10% を全行に均等配分）と温度 1 が重なり、Jev p=0.01 の astra-max が当たった。続きを頼むと同じ行を引き継ぐので 4 回で $13 以上。budget_usd が誰にも書かれず、予算超過の行を外す規律が眠っている。提案：schema 2 で予算必須か規模から既定。続きで予算超過なら選び直す。
  - ID: `R2610-0A-A2`
  - 状態: fixed — commit: `59ff1b19`（pick floor / temperature）; open（budget 必須化と継続時の予算超過対応）
  - 原則: 抽選の探索幅と費用上限を明示し、予算の規律を未記入で無効にしない。
- A3. writes に repo 外への影響を書く場所がない（u24 の作業は E: と r99 に書く）。提案：writes と effects を分ける。
  - ID: `R2610-0A-A3`
  - 状態: open
  - 原則: repo 内の書き込みと repo 外への作用を別々に申告できるようにする。
- A4. 「N finished run(s) remain ungraded」が毎回出る雑音。提案：returned/stopped は自動で採否なし。
  - ID: `R2610-0A-A4`
  - 状態: in progress — ticket: `agx_one_handle`
  - 原則: 採否を要しない終了状態を区別し、毎回の雑音を減らす。
- A5. agx show で動いている作業の中身が分からない（run=… phase=working の 1 行）。
  - ID: `R2610-0A-A5`
  - 状態: in progress — ticket: `agx_one_handle`
  - 原則: 作業の表示は phase だけでなく、進行中の内容を確認できるものにする。
