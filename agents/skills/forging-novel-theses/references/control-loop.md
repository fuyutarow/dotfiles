# control-loop — 反証・タイミング・資本・撤退

Phase 3 の詳細。**着想系の書籍が丸ごと欠く層であり、実利の中心。** 生成（発生）は易しい部分、これは難しい部分。
4 ゲートを全て通す。1 つでも未回答なら、生存計画を欠く。

> **境界メモ**：falsify-and-commit の *一般機構*（最安の反証テスト・kill condition・reversibility sizing）は
> **acting-on-hypotheses (Map/Loop/Leap)** が owner。この 3a・3d はその一般則を *venture-thesis 用に特化*した
> 副ゲートで、3b (why now) と 3c (資本適合) は acting-on-hypotheses に無い venture 固有の層。一般則が要るときは
> そちらへ、生成局面へ戻るときは Phase 1 (generation-engine) へ。

## 3a 反証設計

「この thesis を最も安く殺せる実験は何か」を、実装に入る *前* に書く。殺す実験を設計できない thesis は反証不能
（G3）= 戦略ではなく信仰。合意非依存（Phase 0）の必然的対抗軸がこれ。群衆からの独立 + 自己反証 = 良い認識論。自己反証を
欠く独立は奇人。

**checklist**：
- [ ] この thesis が偽なら、最初に観測される兆候は何か。
- [ ] その兆候を、実装フル投資 *前* に、最も安く引き出す実験は何か。
- [ ] その実験の結果が「殺す / 生かす」を実際に分けるか（どう転んでも続ける実験は反証ではない）。
- [ ] 実験のコスト（時間・資本）は、thesis 全体の投資に対して十分小さいか。

**worked example（皮肉な自己適用）**：着想系の書籍自身が仮説 → 検証のループを持たない。「マスクはこう考えて
いた、だからこの思考法が正しい」は循環論法で、同じロジックで「天才は朝早く起きる」本も書ける。→ 反証設計とは、
この循環に陥らないために「自分の主張を殺す観測」を先に定義する規律。

**deep-tech の型**：thesis が「M（測定・素子）が固定なら補償が fab ばらつきを吸収する」型なら、反証は「補償で
吸収しきれない残差が仕様下限を割る条件」を最小コストで引く実験。理論主張（KKT / f-invariant 等）は、数値の
hard instance を 1 つ作って落とす方が、追加の裏付けを積むより安く殺せる。**確信を支持する証拠を増やすのでは
なく、確信を殺す最安の一撃を探す。**

## 3b タイミング判定（why now）

「なぜ今か」。実現を可能にする条件が今日存在するか、N 年後か。Bill Gross の約 200 社分析で、成功を最も説明した
単一因子はアイデアでもチームでも資金でもなく **タイミング**。生成 4 機能を完璧に実行してもタイミングで死ぬ。

**checklist**：
- [ ] この thesis を「今」可能にする、具体的で名指しできる変化は何か。
  - 規制の変更 / コスト曲線の交差 / 基盤技術の成熟 / 需要側の構造転換 / 標準の確定 / 供給制約の解消。
- [ ] その変化は、5 年前には無かったか（無いなら why now が立つ）。
- [ ] その変化は、5 年後には陳腐化していないか（早すぎ / 遅すぎの両側を見る）。
- [ ] 「今」の根拠が「自分が今やりたいから」に過ぎないなら、それは why now ではない。

**判定の型**：early / on-time / late の 3 値で置く。early は資本を焼き切る（市場が育つ前に息切れ）。late は
差別化が消える。可能化する変化を名指しできない thesis は、タイミング仮説が無い = 賭けの根拠が無い。

## 3c 資本適合

真実が判明するまでの時間（time-to-truth）が、利用可能な資本の runway に収まるか。長期 thesis は長期資本を要求
する。着想系は資金が湧いてくるかのように扱うが、資本配分はそれ自体が独立した技能。

**checklist**：
- [ ] この thesis の核心仮説が「検証される」までに要する時間はどれだけか。
- [ ] その時間、資本（自己資金・grant・VC・売上）は保つか。
- [ ] time-to-truth > runway なら、(i) 検証を早める（安い反証実験に前倒し）、(ii) runway を延ばす（資本源を
  変える）、(iii) beachhead を time-to-truth の短いものに差し替える、のどれで埋めるか。
- [ ] 資本源の horizon と thesis の horizon が一致しているか（短期資本で長期 thesis を回すと、検証前に撤退を
  強いられる）。

**型**：長期 thesis を短期資本で回すのは、Phase 3d の撤退を「仮説が偽だから」ではなく「金が尽きたから」引かせる。
これは最悪の撤退（学習ゼロの死）。資本適合は撤退の質を決める。

---

## 3d 撤退・pivot 基準

「この道が死んでいる」と判定する信号を、事前に定義する。サンクコストに抗うための pre-committed kill-criteria。
持続（諦めない = 英雄の旅）だけの礼賛は生存者バイアス — 崖に向かって「諦めなかった」失敗者は標本に残らない。
持続の逆関数として、撤退能力を第一級で持つ。

**checklist**：
- [ ] 「これが観測されたら撤退／pivot する」という信号を、*着手前* に紙に書いたか。
- [ ] その信号は客観的か（「なんとなく厳しい」ではなく、閾値のある観測）。
- [ ] pivot の場合、何を捨てて何を残すか（生成で得たプリミティブのどれが再利用可能か）を事前に決めたか。
- [ ] 撤退基準を、感情が高ぶる前（着手時の冷静なとき）に固定したか。

**型**：良い撤退は「仮説が偽と判明したから」引く撤退で、学習が残る。悪い撤退は資本枯渇や消耗で引く撤退で、学習が
残らない。3a の反証実験が撤退信号を供給し、3c の資本適合が撤退の時期を守る。3d は 3a・3c の帰結として設計される。

---

## ループとしての運用

Phase 3 は 1 回の判定ではなく反復する制御ループ。生成（Phase 1–2）は静的な線形パイプラインに見えるが、実際の
ベンチャーはループ：

1. 生成した thesis を 3a で殺しにかかる。
2. 生き残ったら 3b で why now を問う。early/late なら wedge（beachhead）を差し替えて Phase 1 に戻る。
3. 3c で資本適合を確認。合わなければ beachhead を time-to-truth の短いものに差し替え、Phase 2 に戻る。
4. 3d で撤退基準を固定。
5. 実装で現実に接触 → 新しい観測 → 1 に戻る。

着想系書籍の欠陥は、この現実接触 → 反復修正のループが無く、着想の発生で記述が終わること。**発生は易しい。生き
延びさせる制御ループが難しく、そこが実利の中心。**
