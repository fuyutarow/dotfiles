# getRun(id) 参照のスコープ付きレビュー

対象は設定済み Relay client を持つ呼び出し側向けの `api.md — getRun(id)` のみ。他ページは評価していない。

## 良い点

- 冒頭の Scope が読者を限定し、セットアップを host guide へ送っている。
- 「書き込みを行わず、外部操作も開始しない」は呼び出し側が副作用を判断する材料になる。
- 「どちらの結果も外部作業が起きたかを確定しない」は、Unavailable 後の扱いを誤らせない重要な注意である。

## 不足・不確かな点

- `NotFound` の「この呼び出し側に見えない Job」は、権限による不可視と存在しない ID の区別を示していない。読者は両者を同じものと扱ってよいのか判断できない。
- `revision` の意味と `queued/running/completed` が全状態か（列挙が網羅的か）が書かれていない。
- `Unavailable` で再試行してよい理由（読み取りの冪等性）は述べられているが、再試行の回数や待ち方は示されていない。
- 成功・失敗の処理は「first-run page」に委ねられており、この参照単独では `ReadError` の全バリアントが分からない。

## 結論

参照としての範囲は適切で、副作用なしと外部作業の不確かさは明確。ただし `NotFound` の意味、状態の網羅性、`ReadError` の完全な列挙は、この参照だけでは確認できない。
