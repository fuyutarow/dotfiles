# Research family — responsibility consolidation

Baseline: f461c37. User asks for MECE split/consolidation of the research-related skills.
Scope: the research knowledge operations, execution/commitment and governance/compatibility owners
listed in agents/skills/README.md, Research responsibility map. Language/tool skills remain executors.

## Partition criterion and decision

Each decision/result has one semantic owner. Tasks and agents may compose multiple decisions;
MECE does not require exclusive subject words, one actor per skill or a compulsory sequential pipeline.
Unknown questions remain explicit OPEN scope, not a claim that all future research is enumerated.

| Operation | Disposition | Reason |
|---|---|---|
| Generic research execution formerly caught by directing-research | Consolidate into BIBIFI; retire the generic legacy trigger | A routing-only return cannot own the requested continued execution |
| Legacy invocation and immutable v1 readers | Retain directing-research for explicit compatibility only | Preserve historical scripts/records without treating them as current research policy |
| Local question clarification bundled with programme formulation | Separate into the current content owner; programme retains portfolio choice/allocation | A partial theory map or supplied local frame requires no new mandate |
| Theory construction/update, proof certification, corpus synthesis | Retain distinct owners | These respectively change a theory, certify an exact statement, and adjudicate a corpus |
| Explanation and seed transformation | Retain the purpose cut established in f461c37 | Different operations may act on the same candidate without duplicating its identity |
| Evidence validity versus costly commitment/risk bounds | Retain VEE versus AOH/Tiger; fix AOH's stale integrity route | A valid measurement does not choose a bet or certify resource integrity |
| Programme, section, fleet roles and dispatch | Retain conditional profile/authority owners | Allocation, local admission, role vocabulary and process control are distinct decisions |
| Repeated family maps | Keep README as the collection map; BIBIFI composition retains only consumption rules | Remove the obsolete mandatory programme staircase and ranked-batch claim |

No skill package is added or physically deleted. Retirement is of duplicate responsibilities and
automatic generic entry, not of compatibility data. Do not report a reduced package count.
Neither this structure nor a test-selection action grants admission/adoption authority.

## Audits and adjudication

Two bounded read-only Terra audits inspected content and execution/authority seams. Root checked
the cited files, chose the partition and applied all changes. Follow-up content review found no
blocking ownership defect. Execution review found generic trigger words and legacy-broad schema
still in the shim; both were removed from its entry surface. Its body retains specific legacy routes.

One proposal to widen corpus openings to theory obligations was rejected: systematizing-theories
already owns those obligations, proving-theorems owns proof work and BIBIFI selects bounded work.
The direct route is now explicit; a new openings conversion would duplicate an existing handoff.

## Verification and limits

The pre-edit family lexical suite failed three groups: a duplicate stale size cap, outdated
corpus/generation wording, and an obsolete orchestration phrase. The revised suite checks the current
semantic boundary tokens; description size remains owned by skill-check and the aggregate ceiling.
No platform limit was raised. Static patterns are not proof of automatic invocation or live behavior.

Current routing cases cover ordinary versus formal-profile work, local theory scope, exact proof,
corpus synthesis, explanation versus transformation, existing theory obligations, costly bets and legacy invocation.
Existing scripts and record schemas are unchanged; only the current routing-decision label changes
from legacy-broad to explicit-legacy. Immutable historical v1 schemas and readers stay intact.
No production R&D experiment, runtime scheduler or source-corpus write is part of this revision.
Source-based scientific contracts from the prior soks-grounded revisions are retained; this is a
skill-supplied responsibility design, not a new scientific result or measured throughput improvement.
