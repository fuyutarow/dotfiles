# orchestrating-agents — 委任体制を運転する監督の規律

> **Version**: v2607.9.0 (2026-07-25) — 役を一つ新設: 外界の観測(grok)。正しさを問う役と、
> 外界が何を言っているかを問う役を分けた。.8.1 は上位実務の harness 内外への分割と sol の排他、
> .8.0 は担い手の更新(監督=Opus 5)。履歴・実測・改名の記録は tests/forge-verification-ledger.md。

## 目的と適用範囲

この skill は、決まった仕事を委任体制で速く回す。

分野固有の判断は、対応する project skill に委ねる。

各 gate は、機械で確認できる artifact を要求する。

## LAW

結論は、生産と検証を並列に進め、監督の実務を禁止することだ。

| LAW | 規則 | artifact | 出自 |
|---|---|---|---|
| (1) 公表門 | 検証は公表を止める門である。生産を止める門ではない。 | 生産と検証が同じ巡で進んでいる。 | 2026-07-22、台帳 §再定義 |
|  | 生産と検証を並列に走らせる。 | 計算・試作・起草の発射記録がある。 | 2026-07-22、台帳 §再定義 |
|  | 委任の往復は一巡ごとに機構で削る。 | 同型指摘の処理が P4 に従う。 | 2026-07-22、台帳 §採択 |
|  | 前進のない応答は作らない。 | 前進がなければ空の状態報告もない。 | 2026-07-22、台帳 §却下 |
| (2) 実務禁止 | 監督は手を動かさない。 | 監督の行為が宣言制で分類されている。 | 2026-07-22、台帳 §一致所見 |
|  | 監督は設計・指示書・裁定・検収・対話だけを行う。 | 監督による分単位の実装・整形・探索・計測がない。 | 2026-07-22、台帳 §採択 |
|  | 実装・整形・探索・計測は実務へ委任する。 | 実務の発射先と指示書が記録されている。 | 2026-07-22、台帳 §採択 |

### 配役の根拠

一次錨は次の三つの逐語引用である。

```text
"Claude Fable 5 is significantly more dependable at dispatching and
sustaining parallel subagents, and reliably manages ongoing communication
with long-running subagents and peer agents."
```

引用1は、並列 subagent の持続管理を錨づける。

```text
"Claude Fable 5 dispatches parallel subagents more readily than prior
models. Use subagents frequently, provide explicit guidance about when
delegation is appropriate, and prefer asynchronous communication between
orchestrator and subagents over blocking until each subagent returns."
```

引用2は、P2 の非同期・非 blocking 原則までを錨づける。

引用2は、C2 の10分閾値を錨づけない。

```text
"Fable 5 draws from your plan's regular weekly usage limits and uses them
faster than other Claude models."
```

引用3は、監督と実務の費用の非対称を錨づける。

「持続しない」は引用の含意ではない。

`Fable=Director / Sonnet=Executor` は公式推奨ではない。

Sonnet への束縛は家の裁定である。

出自: 2026-07-24、台帳 §配役の一次錨。

agentic coding and enterprise work. For workloads that need the highest

### 外部艦隊の配役(2026-07-25)

上位の実務には形の違う担い手が二つある。級ではなく形で選ぶ。

| 仕事の形 | 担い手 | 理由 |
|---|---|---|
| この session の文脈・作業木の中で着地させる単発 | Fable 5 | 会話と作業木を共有する。返り値がそのまま文脈に載る |
| 広い掃引を指示書で渡し、成果物で回収できる仕事 | sol の ultra | 外部で艦隊を組む。費用が別契約に載る |
| 独立の第二意見 | sol または agy | 盲検で渡す。実務側の結論を渡さない |

sol を実務へ降ろすと、その仕事の異種監査人が消える。自己監査は検収ではない。

したがって sol を実務に使った仕事は terra を既定の監査人とする(P6 の既定の例外)。

terra は同一ベンダ同一世代のため独立性は部分的である。判定が割れたら agy を足す。

費用の非対称は形の選択にも効く。sol の ultra は Anthropic の週次上限を消費しない。

遊休の契約capacityがあるとき、上位の実務は harness 外から先に当たる。

出自: 2026-07-25、台帳 §外部艦隊の配役。

### 外界の観測の配役(2026-07-25)

委任体制には、正しさを問う役とは別に、外界が何を言っているかを問う役がいる。

技術的な真偽は一次資料で決まるが、世評はそれでは決まらない。

社会との接点を持つ判断は、受容・不満・話題の所在を観測しないと選定を誤る。

| 問いの形 | 担い手 | 返るもの |
|---|---|---|
| これは正しいか | sol・agy・自前の計算 | 独立の検証 |
| これはどう受け取られているか | grok | 世評と個人の所感の集約 |
| いま何が起きているか | grok・web 検索 | 直近の話題と一次記事 |

送るのは問いであって repo ではないため、EXFIL の制約は発火しない。

したがって「秘密を含む repo に向けない」は、監査用途に固有の制限である。

観測の産物は「何が言われているか」であり、「何が正しいか」ではない。

世評を技術的主張の根拠へ転用すると P6 が壊れる。別の種類の事実である。

この配役は発注者の裁定であって、能力の実測ではない。

常設への昇格には C4 の実測が要る。通すまでは暫定の担い手として扱う。

比較の設計(測る量と baseline の腕)は台帳 §外界の観測の配役にある。

出自: 2026-07-25、台帳 §外界の観測の配役。

## MUST-NOT-FIRE と fire/no-fire

発火面は委任体制の運転に限定する。

### FIRES

| ask |
|---|
| 「研究を進めて」 |
| 「どんどん進めて」「さっさとやれ」。制作の文脈に限る。 |
| 「起草と査読を委任して」 |
| 「複数の模型に相談して水平思考」 |
| 「定理・文書を起草・査読させて」 |
| 「仕事が遅い」「生産性が低い」「生産性を上げろ」 |
| 「ポストモーテムの是正を適用」 |
| 「監督としてどう振る舞うべきか」 |
| 「委任体制をどう運転するか」 |
| 「誰に任せるか決めて」「モデルの配役を決めて」 |
| 「中間生成物を毎回作り直している」 |
| 「束ねのキャッシュが効いていない」 |
| 「検収の試験をどう設計するか」 |
| 「完成宣言が監査に落ち続ける」 |
| 「Fable に全部やらせていい？」 |
| 「監督自身が直接全力でやれ」 |
| 「委任体制でのモデルの役割分担」 |
| 「Fable を作業者にすると枠が溶ける」 |

「定理・文書を起草・査読させて」は `proving-theorems` と共発火できる。

委任の運転はここが持ち、数学の中身は同 sibling が持つ。

### MUST NOT fire

| ask | route |
|---|---|
| 個別 CLI の flag・model 指定・呼び出しの正しさ | `driving-codex` 等の driving-* 系 |
| 文献体系化の台帳・確度・矛盾調停の作法 | `systematizing-knowledge` |
| 次に何をやるべきかの選定・撤退判断 | `directing-research` |
| 文章規則の中身・語の登録 | `linting-prose` と環境の検査設定 |
| 対象分野の事実・位置づけの判断 | その分野の project skill |
| スキル設計の craft | `forging-skills` |
| 一行の質問への即答 | skill 不要 |
