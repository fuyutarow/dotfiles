## 認可判定は「渡されたスナップショットに対する真偽値」である

Gatelet に渡すのは、認証済みの subject、リソースの policy、そして subject が現時点で持つ grant のスナップショットです。認証と grant の発行はアプリケーションの仕事で、Gatelet は関与しません。Gatelet が返すのは boolean だけです。true であってもファイルの読み書きなど外部への作用は起きないため、保護したい操作を実行する直前に、アプリケーション自身が判定結果を確認する必要があります。

policy は read と write に分かれ、それぞれ clause のリストです。リスト内は OR で、どれか一つが一致すれば許可になります。リストが空なら拒否です。拒否の clause はなく、親フォルダからの暗黙の継承もありません。

clause は二種類です。Owner は、そのリソースについて明示的に供給された所有者の証明と一致します。Grant(scope, mask) は、scope が完全に等しく、かつ mask の共通部分が 0 でない grant と一致します。判定の要点は「共通の bit が一つでもあればよい」ことです。clause の mask の全 bit を持つ必要はありません。bit の意味はアプリケーションが定義します。

grant は一つずつ独立に照合されます。ある grant が一致しなくても、別の grant が一致すれば結果は true です。異なる scope の grant を合成して新しい grant を作ることはありません。そのため、一つの grant を外しても、別の有効な grant が同じ操作を独立に許しているなら、アクセスは残ります。

判定は渡されたスナップショットについてだけ成り立ちます。grant の状態が変わったら、アプリケーションは判定をやり直す必要があります。Gatelet は grant の取り消しや状態の保持を行わず、キャッシュ無効化の仕組みも提供しません。また、grant を変更しても、利用者がすでに得たデータが消えるわけではありません。
