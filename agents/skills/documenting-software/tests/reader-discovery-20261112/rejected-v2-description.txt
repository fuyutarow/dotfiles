  which readers the product and its dependencies imply, what each needs to decide, and where the
  page path answers or leaves them guessing; discover needs the user has not named. Assign page
  responsibilities before directories. Separate guarantees, design choices, coding rules and editorial
  records: input rejection is a guarantee; converter choice is design; unsafe-cast bans are coding
  policy. Preserve binding rules when moving them. Begin with the technical answer. Verify
  reader consequences against text and links within the reviewed product/task. A narrow reference
  stays within its declared context. Use for README,
  guides, API docs, specs and ADR/RFC.
