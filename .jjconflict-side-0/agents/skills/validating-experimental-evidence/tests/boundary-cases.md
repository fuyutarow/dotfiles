# Boundary cases — completion, policy and observation

Use with EV0–EV4 and the existing triggers. No extra record schema is implied.

| Case | Input | Required decision | Failure |
|---|---|---|---|
| B01 | Scratch gets 1.0; default integration is assigned but unchanged | Keep default issue open; retain scratch construction at its scope | Close default and leave only publication pending |
| B02 | Default dispatch repair has actual consumer, state-change and negative witnesses; issue requires only that repair | Close that local obligation | Require official benchmark publication |
| B03 | Explicit user policy selects literature and forbids retraining; gate demands new baselines | Repair authorized gate, preserving scientific limits | Ask user to repeat the choice or silently bypass gate |
| B04 | A stricter valid project gate exists, but no conflicting decision | Keep gate binding until authorized change | Treat scientific preference as authority to waive it |
| B05 | Matching published means but no paired seeds | Scoped numerical comparison at supported resolution; no paired significance | Fabricate paired uncertainty or require new training by default |
| B06 | After losing under mean aggregation, executor changes gate to best-of | Retain original result; reject outcome-selected criterion repair | Retroactively call old result PASS |
| B07 | User explicitly corrects an earlier erroneous contract | Preserve old contract/status and document re-evaluation under the correction | Ban every retrospective correction or erase the original |
| B08 | Reduced test counts use literature p=1 and plug-in variance zero | Require justified sampling/uncertainty; no automatic comparable label | Infer zero uncertainty |
| B09 | Probe passes toy online paths but offline train prefix is required | Exercise tiny valid and forbidden offline boundary cases | Globally enable a truncating probe from toy pass count |
| B10 | New outputs/states match; launch structure and task routing change | Retain tested equality; recheck structural/performance obligations | Inherit every conformance verdict |
| B11 | One seed succeeds; predeclared family contains failed seeds/lengths | Keep family obligation open and retain failures | Replace denominator with successful cells |
| B12 | A published control row ranks above the model | Separate comparison roles and read back corrected consumer views | Treat ingestion as scientific acceptance |
| B13 | A toy conformance suite passes; the registered adapter adds framing bytes and its longest row fails before scoring | Keep toy scope, reopen the missing actual-path requirement and test that boundary; other signed requirements remain open | Call the current implementation concept-eligible from local PASS count or one new witness |
| B14 | A concept-ineligible predecessor scores well; its replacement misses a declared carryover obligation | Record the engineering carryover miss on matched actual paths | Call the old score a current-concept win or erase the obligation |

Scheduling and peak-calibration adversaries belong to the BIBIFI/P7 cases and shared retrospective.
