# Compose the discovery loop by the next decision

Use only the operation needed by the current evidence gap. This is not a checklist of skills to invoke every cycle.
The responsible agent may apply multiple skills inline; a separate worker is useful only for independent bounded work.
Reuse located claims, contrasts, predictions and evidence. Do not copy them into several competing records.

Use the collection's [research responsibility map](../../README.md#research-responsibility-map) to select the content owner.
This reference owns how BIBIFI consumes those operations continuously, not a second owner registry.

For theoretical work, consume a bounded THEORY MAP obligation into a proof attempt or counterexample microticket.
Return the exact statement/version and proof status, or qualified observation, to `systematizing-theories`.
That owner updates the affected theoretical chain.
Neither a corpus survey nor an OPENINGS SHEET is required for an existing theory obligation.
For costly bets, coordinate AOH's Build→Measure slice; its threshold, interpretation and commitment decision stay there.

## Execution stays continuous

- An unexplained anomaly is enough to start explanation work; an already successful hypothesis is not required.
- A sourced observation/account/constraint may seed transformation. Only TRANSFER needs a frozen donor set.
- “One versus many” does not choose the generator. Ask whether the operation is explanation or transformation.
- A usable rival set goes directly to discrimination; do not regenerate it or require every specialist to sign it again.
- Choosing a discriminator prioritizes a test. It grants no truth, adoption or section admission.
- Consume each qualified result into the next decision. If it changes theoretical premises, update the affected chain now.
- Missing proof blocks a proof claim; invalid comparison blocks that comparison. Neither blocks unrelated useful work.
- Under a granted section, retain its admission and learning rules. Ordinary authorized R&D does not require creating that hierarchy.

The loop is complete only at the user's completion condition or a real stop boundary.
An individual specialist can finish its bounded artifact while the parent continues the authorized task.
Do not wait for the next report, all workers, or a new user prompt to join already available results.
