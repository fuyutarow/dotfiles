# Claude Code AGENTS.md loading path (2026-10-21)

## Finding

Installed Claude Code is `2.1.306` (`claude --version`). Anthropic's current [memory and instruction-file documentation](https://code.claude.com/docs/en/memory) says direct `AGENTS.md` loading requires `2.1.277+`; the installed version meets that floor. This is version-bound support, not a claim that every session loads AGENTS.

Default project-instruction mode is `claude-md-or-agents-md`: Claude loads project `AGENTS.md` only when there is no `CLAUDE.md`, `.claude/CLAUDE.md`, or `CLAUDE.local.md` in the working directory or an ancestor. `~/.claude/CLAUDE.md` does not suppress it. The repo root currently has both `AGENTS.md` and `CLAUDE.md`, so under the documented default the root `CLAUDE.md` wins and root `AGENTS.md` is not loaded directly.

The local CLI help confirms that normal startup auto-discovers `CLAUDE.md` and that `--bare` disables that discovery, but it does not describe AGENTS behavior. The current project and rendered user settings contain no `pluginConfigs` override. A saved `/config` Project instructions choice or disabled built-in AGENTS plugin is runtime state not evidenced by these files, so that state remains **unknown**.

## Adapter, cycles, and removal conditions

- No current root `CLAUDE.md` `@AGENTS.md` import is configured. The exact-content search found `@AGENTS.md` only in archived workaround material; the root file itself contains no such import.
- The local absence of an import does not imply native support is absent: official docs say native support is enabled by default from `2.1.277`, subject to Project instructions mode and the built-in plugin.
- After removing root `CLAUDE.md`, root `AGENTS.md` is the native project path on the installed version under the documented default. Remove/rewrite `AGENTS.md:3` at the same time so it does not direct agents back to the deleted file.
- Before removal, verify the session's Project instructions mode is not `claude-md` and the built-in AGENTS plugin is enabled. The observed home and project settings have no `pluginConfigs`; neither file declares an override.
- If a fallback is required for sessions that cannot use native AGENTS, keep a project-root `CLAUDE.md` containing `@AGENTS.md`. That makes root AGENTS explicit import input; it is not needed for the normal native path above. Do not create both a back-reference from AGENTS to CLAUDE and this import: that forms a read cycle. Official docs say imported AGENTS is not loaded twice when both mechanisms are enabled.
- No home renderer, `agents/claude/CLAUDE.md`, `agents/claude/settings.json`, or `scripts/config-registry.ts` change is needed for project-root AGENTS. Those files own the distinct user-global surfaces. The migration write set is the project root `AGENTS.md` (remove the stale CLAUDE reference) and root `CLAUDE.md` (remove it, or retain only the explicit fallback import if the owner chooses compatibility over deletion).
