# Execution model — observable evidence

> **SOLE owner:** this skill's delegation stages and return schema.
> Generic dispatch contracts and aggregate resources belong to `orchestrating-agents`.

Evidence type: **TIERED-OBSERVABLE**.
Agents can relay inspected sources and observed checks.
They cannot establish future reliability or causal coding-agent benefits by agreement.

## Stage map

| Stage | Mode | Why |
|---|---|---|
| T0 design choices | SOLO | State ownership and resource bounds must compose |
| T1 tier and T2 obligations | SOLO | Consequences and contracts need one interpretation |
| Independent boundary or tool facts | Optional read-only fan-out | Each fact can carry its own observable locus |
| Reconciliation | SOLO after relevant returns | Conflicts must be checked against sources |
| T3 exceptions and T4 acceptance | SOLO | They allocate residual risk |

## Return contract

Use the complete briefing contract from `orchestrating-agents`.
Add only these domain fields:

```yaml
lens: architecture-boundary-fact | language-fact | tool-oracle-fact
scope: one proposition and regime
read_only: true
return: [proposition, locus, observable, applicability_boundary, unverified]
forbidden: [architecture-choice, tier-or-release-decision, causal-LLM-effect-claim, target-edit]
```

Missing loci, ambiguous regimes, or unrun checks cannot close a ledger row.
A machine verdict validates only the property its invocation checks.
If acting as a review lens, return findings, affected row IDs, and clearing conditions.

## Scale

| Case | Execution |
|---|---|
| One design/review/promotion | SOLO, zero agents |
| One material independent uncertainty | One focused fact pass if delegation is available |
| Several independent boundary facts | Separate read-only passes; reconcile only relevant dependencies |

Never spawn an agent for routine grep, tests, or resource reservation.
No harness → same map, serial.
This execution policy is skill-supplied; lineage lives in `source-ledger.md`.
