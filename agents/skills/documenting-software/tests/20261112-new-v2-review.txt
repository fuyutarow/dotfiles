## 主要な発見（重要度順）
1. **完了条件が一致しない。** I-ACCEPTANCE（product.toml L1172）は T1–T4 を完了とし、T の usecase_ids（L5, L13, L20, L28）に UC11・UC12–UC19 は入らない。一方 acceptance.md L47・L68 は UC1–UC11 と §4 の UC12–UC18 を必須とする。さらに T1–T10 の tests はすべて空（L6–L76）。読者は完了を判定できない。
2. **11/09 追加操作が story につながらない。** UC11–UC19 の stories_covered はすべて空（L790, L818, L839, L860, L881, L902, L923, L944, L989）。acceptance.md L49–56 の C1/C2/C3/C6 は product.toml に現れず、L47 の説明だけでは対応を検証できない。
3. **送信失敗の意味が未定義。** S5 は「確定しない（PortFailure）」とだけ書き（db.md L121）、不成立か結果不明かを分けない。S4 の出力は Effects のみ（L120）。I-IMPORT-FINALITY（product.toml L967）は送信前に最終 bytes の digest を checkpoint せよと求めるが、db.md の S2（L109）は bytes しか返さない。再送の安全性は db.md だけでは判断できない（N-IMPORT-UNKNOWN-RESUBMIT, L960）。digest の取得が db 外にある可能性は推論。
4. **同一文字列の反復。** `write_issue_derivation` が 24 件同文で並ぶ（product.toml L117–L370）。A-COLLAB 4 行の text も同文（L375, L388, L401, L414）。修正時の食い違いを生み、セル間の差が見えない。
5. **件数の不一致。** I-FOUR は 16+35+2+7 = 60 項目（L1025）、I-TRIPLE のテスト名は「all 64 manual field values」（L1079）。どちらが現行か文書からは決まらない。
6. **ID の接頭辞が意味を持たない。** db.md L76 は S11 を Query 節（L93）で使い、§7（L118）の保存・署名・送信の S 系と並ぶ。
7. **参照先の所在が示されない。** 受入れ台帳（acceptance.md L13, L73）、対象資料一覧（L9）、layers.toml（architecture.md L13）、core.toml（db.md L7）は、この文書群では所在も内容も検証できない。
