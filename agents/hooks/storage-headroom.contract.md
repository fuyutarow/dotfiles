# CONFIGURATION CONTRACT — storage-headroom

The configuration system behind `enforce-storage-headroom.ts`. The config says WHAT is guarded;
the hook is the mechanism.

- Consumer: runtime — the `enforce-storage-headroom.ts` PreToolUse hook runs for every tool call from Claude Code and Codex and reads this config for non-allowlisted calls; a human editor authors it
- Authority / writer: the dotfiles owner, by commit to this repo
- Effective configuration: `agents/hooks/storage-headroom.toml`, read through the `~/.claude/hooks` symlink; `STORAGE_HEADROOM_CONFIG` replaces the path for the test suite only
- Source representation: TOML, parsed by Bun's built-in `Bun.TOML.parse` (hooks stay zero-dep)
- Trust regime: human-authored
- Signature / digest input: n/a
- Canonicalization profile: n/a
- Schema / version: `schema = 1`; shared drive thresholds and line math come from `tools/shared/src/storage-headroom.ts`, while the hook validates its remaining fields in `validate()`
- Host recovery floor: `drive.host.stop_gib` is read by `scripts/wsl-capacity-recover.ts`; it must be below `drive.host.deny_gib`. The hook queues `wsl-capacity-recover.service` below the deny line, while its timer covers already-running work. The service first tries `reclaim:host`, `reclaim:builds`, and `reclaim:clean`; below `stop_gib` it stops recognized compute before cleanup, then runs `cargo clean` in the known polysearch workspace only after build processes exit. It also samples Windows available RAM and hard page reads, drops guest page cache through Windows `wsl.exe -u root` on severe pressure, and stops compute if pressure remains.
- Drive lines: each `[drive.*]` line is min(`deny_gib` GiB, `deny_pct`% of that drive's size) — and likewise `warn_gib`/`warn_pct`, which come as a pair. Both halves are required, so an absolute size set on a 1 TB disk never judges a 40 GB one alone (2026-10-05: a rented box was denied every launch with its disk 80% empty). `stop_gib` stays absolute: only the host recovery script reads it.
- Tool gating: only disk-writing tools are checked: Bash (by parsed command), `Write`, `Edit`, `MultiEdit`, and `NotebookEdit`. Codex `exec_command`, `shell`, and code-mode `exec` arrive as Bash. Other tools, including `Read`, `Grep`, `Glob`, `SendMessage`, `ListAgents`, `AskUserQuestion`, `TaskStop`, `ToolSearch`, and MCP read tools, pass without a storage measurement. A checked tool is denied below a drive's deny line except the command allowlist. Bash commands are parsed structurally and every command in a chain must be allowlisted. Cleanup exceptions are `disk-reclaim`, `storage-headroom`, `mise run reclaim*`, `m reclaim*`, scoped `cargo clean` (cwd or `--manifest-path` directory must contain `Cargo.toml`), `jj workspace forget`, and `jj abandon`. `agx dispatch|resume|grade|ack|stats` are allowed because ticket write scope cannot be determined from the command line; dispatch writes small state files and spawned workers remain individually gated. Read-only Bash exceptions are `df`, `du`, `dust`, `ls`, `cat`, `head`, `tail`, `rr`, `jj st`, `jj log`, and `jj workspace list`.
- Workspace safety: `jj workspace add --help` and `-h` are always allowed. A non-sparse add is denied when the default workspace checkout exceeds `sparse_required_above_mb` in `storage-headroom.toml` (default 500 MB); cache entries keyed by repository root expire after one hour. When size is unknown, a synchronous `jj file list` count has a 2 s bound and is cached with its timestamp. At most 10,000 tracked files allows the add immediately. Above that count, or if the count probe fails, a synchronous `du` size probe has a 5 s bound; its result is cached and checked against the configured threshold. If both probes time out, the hook denies and names the timed-out probes. `jj file list` enumerates tree entries without reading file contents. The recommended route is `jj workspace add --sparse-patterns empty <dir>`, then `jj sparse set --add <paths>`; sparse adds still follow the ordinary storage deny line.
- Launcher matching: commands in `launcher` are denied at the warn line. Other tool calls are denied only at the deny line. Between the lines, calls pass with `additionalContext` naming the measured free space and `disk-reclaim plan`; above the warn line they pass silently.
- Free-space cache: statfs results are stored under `~/.cache/claude-hooks/storage-headroom` and expire after at most 2 seconds. Artifact-size cache remains governed by `measure.cache_minutes`.
- Cargo target budget: the same target-directory measurement applies to direct Cargo and the `mise run` / `m` build tasks. At 30 GiB it adds cleanup advice; at 80 GiB it denies another build while leaving `cargo clean` and `reclaim:*` callable. The size cache expires after `measure.cache_minutes`.
- Duplicate-key policy: reject — a TOML parse error, reported as "is not valid TOML" in a deny
- Number / Unicode policy: every size and bound is a finite non-negative TOML number (GiB, seconds, minutes); strings are UTF-8 and must be non-empty; launcher commands must match `[A-Za-z0-9._-]+`
- Precedence / merge: one file, no merge and no defaults; an unknown key, wrong type, or missing field makes the whole config invalid, and every error is reported in one deny
- Decision record: none: the effective declaration's writer is the sole authority; the reason for each number is a comment beside it in the TOML
- Deny advice: names each short drive with exact free bytes and deny-line bytes, then lists up to five safe blind-tier reclaim candidates and their cached sizes. The hook reads a capped, one-hour cache and never scans for candidates. The first line gives the single safe action command, `disk-reclaim run --tier blind --yes`. `rip` must not be used to free overlay space.
- Verification command: `bun test agents/hooks/tests/*storage*`
- Positive case: above the warn line, any tool call returns no decision; below the deny line, non-disk-writing tools and allowlisted cleanup/read-only Bash commands return no decision, including scoped `cargo clean` and the named `agx` subcommands; an unknown-size checkout with at most 10,000 tracked files is allowed on the first call and its cached count is reused on the next call
- Negative case: below the deny line, unlisted Bash writes and file-write tools are denied, including writes chained after an allowlisted command; launcher entries are also denied below the warn line. A non-sparse jj workspace add above the configured checkout-size threshold is denied; when both bounded checkout probes time out, the hook denies and names each timed-out probe; sparse adds are still denied below the ordinary deny line.
