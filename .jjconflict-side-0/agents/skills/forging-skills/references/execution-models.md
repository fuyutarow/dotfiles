# Execution models — add the coordination the task needs

> Scope: domain delegation boundaries. Generic dispatch and resources belong to `orchestrating-agents`.

## Step A — decide whether a model is needed

| Task shape | Guidance |
|---|---|
| Short self-contained procedure | Ordinary instructions; no fleet or stage map |
| Delicate tool sequence | Preconditions, failure handling and execution checks |
| Genuinely separable evidence work | Disjoint scope, useful returns and a trust boundary |
| Multiple actors changing shared/durable state | Ownership, visibility, dependencies and acceptance |
| Required service, participant or verifier unavailable | Supported reduced claim or stated blocker |

A reusable skill need not be delegable.
Do not add an execution section or frontmatter clause just because agents exist.
Do not require every invocation to run a workflow.

## Step B — identify evidence and its limits

| Evidence required | Contribution | Limitation |
|---|---|---|
| Source or present-state observation | Locator, observed output and scope | Conclusion without its basis is insufficient |
| Real human behavior or costly signal | Authorized observation of the participant/process | Role-playing cannot supply it |
| Candidate challenge or counterexample | Concrete candidate and discriminating check | Repeated agreement does not establish novelty or truth |
| Future or counterfactual claim | Assumptions and supported forecast method | Present data is not direct observation of the future |
| Machine-checked formal result | Exact statement, assumptions, checker and receipt | Correctness does not establish target faithfulness |

These are lenses, not an exhaustive taxonomy every skill must instantiate.
Retain the domain owner's evidence contract.
Do not strengthen local constraints into universal claims about model outputs.

## Step C — specify the delegated slice

Use relevant fields in the existing brief or owner record.

| Field | Include when |
|---|---|
| Scope and interface | Work is delegated |
| Return and acceptance criterion | A consumer acts on the result |
| Dependencies and safe stop | Work can conflict or become obsolete |
| Evidence and provenance | A factual or behavioral claim depends on the return |
| Visibility and author/verifier separation | Independence or protected information matters |
| Resource and lifetime bounds | The actual dispatch/compute contract requires them |
| Serial or reduced path | It preserves the claimed result with available capabilities |

A seven-component framework, model-lineage sentence and fleet-size table are not mandatory.
Carry the target-specific delta; generic mechanics remain with their owner.
Use the independent observations needed for the disputed decision.
A fixed agent count does not establish coverage.

## Step D — place and validate

Keep a short rule inline if the normal invocation needs it.
Put substantial conditional coordination beside the procedure it constrains.
Use a dedicated reference when the workflow needs that much machinery.
Describe delegation in frontmatter only when it helps selection.

| Verification | Claim allowed |
|---|---|
| Structure and static review | Instruction or package consistency |
| Same-context serial decisions | Scoped review; no independent consensus |
| Independent frozen-input execution | Observed behavior on those inputs and host |
| Matched old/new runs | Comparative result under stated conditions |

Do not demand external actions or expensive evaluations to satisfy a template.
Use existing launchers and bounded environments for authorized rehearsal.
Inspect actual actions and read-back when a tool sequence changes.
If serial fallback loses independence or a required capability, state that loss.

## Failure cases

| Failure | Repair |
|---|---|
| An agent runs a deterministic regex | Shared checker |
| Tiny task burdened with briefs and barriers | Remove unnecessary coordination |
| Author self-evaluation counted as independent | Change separation or weaken the claim |
| Evaluator receives expected findings | Neutral task, criteria and raw artifacts |
| Identical votes counted as independent | Inspect shared contexts, sources and methods |
| Unavailable runtime replaced by prose | Leave execution unverified |
| Constraint resists every contrary observation | Name its prevented failure and retirement condition |
