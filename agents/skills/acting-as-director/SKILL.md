## LAW

> **(1) 検証は「公表を止める門」であって「生産を止める門」ではない。**
> 生産(計算・試作・起草)と検証(相談・照合・裏づけ)は並列に走らせる。
> 委任の往復は一巡ごとに機構で削る。前進の無い応答は作らない。
>
> **(2) 監督は手を動かさない。**
> 監督の文脈に置いてよい行為は 設計・指示書・裁定・検収・対話 のみ。分単位の実装・整形・
> 探索・計測が監督の応答に現れたら、それ自体が違反 ── 委任せよ。
> 行為の分類は**宣言制**(事後の推定ではなく、行為の時点で監督が級を宣言する):
> - **検分** = 読み取り専用の現物確認。1〜2 操作以内。どの裁定を養うかを名指しする。編集・生成・計測は禁止
> - **委任** = 指示書の発行。完成の定義と検収の試験を含む(下の委任契約)
> - **検収** = 検収の試験を実行し、採否と根拠を記録する。新規の実装・起草は禁止。試験は
>   「主張が真なら出る観測」ではなく「**主張が偽なら落ちる独立照合**」でなければならない ──
>   各試験に「この観測は主張が偽でも出得るか」を先に問い、出得るなら試験として無効。差の
>   観測(A≠B になった)より一致の機械照合(出力 = 独立に計算した参照量)を要求する
>   (2026-07-23実測: firedancer GB110 で完成宣言が監査に4巡連続棄却 ──「主指標と
>   min(best,final) が別値」の観測を是正の実証と読んだが、それは GPU cache 汚染のバグでも
>   出るものだった)
> artifact: 監督の応答内の各 tool 呼び出しが上の三級のどれかに宣言済みで、どれにも
> 入らない行為が存在しないこと。宣言できない行為はそれ自体が違反。検収の記録には各試験の
> 「主張が偽でも出得るか」への回答が明記されていること ── 無回答、または「出得る」の
> 試験を根拠に採択した記録は違反。

## 委任の形の選択(2026-07-22 第3次ポストモーテムから)

発注の前に、作業の形から委任の形を選ぶ。当夜の実測: 16件中、形を誤ったのは
「規模の大きい新規実装を単一の腕へ」の1件だけで、それが44分の無音を作った。

| 作業の形 | 委任の形 |
|---|---|
| 読解・検証・独立な計測 | 並列の腕(2〜5腕)。schema で出力を固定 |
| 小さい実装・計測(見積り20分未満) | 単一の腕+時間予算 |
| **規模の大きい新規実装** | **必ず分解**: 監督が界面の仕様を固定 → 土台1腕(自己試験つき) → 部品を並列の腕 → 統合は script のコード(agent を使わない) |

規則:
- **界面の仕様は監督の設計物**。課題・入出力の契約・指標・合否・既存資産の流用指定
  (P10)までを発注の前に書く。仕様が書けない委任は、まだ発注の段階に達していない。
- 依存は管路(pipeline)、独立は並列(parallel)、決定的な処理(結合・採否の規則)は
  script のコードで書く——agent は判断が要る仕事にだけ使う。
- **救済の規則**: 締め切り超過でも納品物が**自己試験を通過済み**なら、腕を停止して検収の
  走行へ切り替える(分解しての再発注は納品済みの土台を無駄にする)。着地だけの未検証の
  納品物を走らせてはならない(2026-07-22 実測: 停止時点の未検証版が実計算の途中で崩壊)。

artifact: 大きい実装の発注に、界面の仕様と分解(土台→並列→統合)が存在すること。

## 堆積の門

門(P-gate + 委任契約内の非番号項目)が合計 12 を超える、または二つの門の発火条件が
重なったら、追記を止めて鍛え直す(統合・昇格・廃止)。現在の合計は 12(P0〜P4・P6〜P10 の 9
(P5 は P2 へ統合済み・2026-07-23)+ 旧P5の吸収を除く番号は据え置き + 委任契約の
指示書の自己完結・生成者≠査読者≠検収者の 2 + P0 の 1)── この節自体が artifact であり、
「監督の一巡」の行を数えれば検証できる。

## MUST-NOT-FIRE と fire/no-fire(desk-check 用)

FIRES: 「研究を進めて」「どんどん進めて/さっさとやれ(制作の文脈)」「起草と査読を委任して」
「複数の模型に相談して水平思考」「定理・文書を起草・査読させて」
「仕事が遅い/生産性が低い/生産性を上げろ/ポストモーテムの是正を適用」
「監督としてどう振る舞うべきか」「委任体制をどう運転するか」
「誰に任せるか決めて/モデルの配役を決めて」
「中間生成物を毎回作り直している/束ねのキャッシュが効いていない」
「検収の試験をどう設計するか」「完成宣言が監査に落ち続ける」。

MUST NOT fire(route):

| ask | route |
|---|---|
| 個別 CLI の flag・model 指定・呼び出しの正しさ | `driving-codex` 等の driving-* 系 |
| 文献体系化の台帳・確度・矛盾調停の作法 | `systematizing-knowledge` |
| 次に何をやるべきかの選定・撤退判断 | `directing-research` |
| 文章規則の中身・語の登録 | `linting-prose` と環境の検査設定 |
| 対象分野の事実・位置づけの判断 | その分野の project skill |
| スキル設計の craft(SKILL.md 自体の作成・鍛え直し) | `forging-skills` |
| 一行の質問への即答 | skill 不要 |
