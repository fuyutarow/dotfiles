# Target benchmark loop — selecting work toward an authorized result

Use only when the user or a signed domain artifact names a benchmark outcome.
The goal's acceptance predicate is authoritative. This reference chooses work;
`validating-experimental-evidence` owns whether a row supports a claim.

Read the existing registry and evidence records. Keep no second score or status store.
Bind the target implementation, signed concept requirement, suite and metric.
Also bind the comparator and accepted-result criterion. `UNKNOWN` is not a win.

| Current observable | Next decision-changing work | What remains unearned |
|---|---|---|
| No target predicate or benchmark binding | Freeze the smallest target, concept and scoring contract with its owner; obtain EV0's binding | A numerical win or release ETA based on an undefined target |
| Current implementation's concept status is `FAIL` or `UNKNOWN` | Exercise the actual learning and inference path against the missing requirement; repair the first failing consumer | Achievement credit for a prior or scratch implementation |
| Eligible current path, registered members unmeasured | Run bounded coverage on that path and record member-level outcome; expand to required seeds/lengths only under the accepted protocol | Whole-suite coverage from a smoke or host reference |
| Valid current row with no comparison headroom | Preserve the tie or ceiling; select another authorized member with headroom | Calling a tie a literature breakthrough |
| Valid current row below target | Localize one failure on the same path, then test the smallest mechanism change that could raise that row | A new theory or helper count as score progress |
| Interface or launcher blocks the row | Repair the first executable/scored path, then obtain its actual run receipt | Treating a plan, registration or attempted launch as a measurement |
| No authorized member has headroom | Report the bound and route a proposed new standard target to its domain owner | Quietly replacing the comparison set after seeing results |

Before a host proof, survey, redesign or broad audit, name the target row or concept
test it will change. Name the consuming implementation step and first return.

If the result cannot affect that path, defer it. A necessary theorem or apparatus
repair may still be critical work.

Ask `validating-experimental-evidence` for each row's validity, footing and concept
eligibility. Keep counts separate: registered, current-path measured, qualified,
and accepted wins. A result in a prior concept-ineligible edition is a reference
or transfer candidate, not a current win. A failed row is valid negative evidence
when its measurement passes; preserve it.

Lead a progress report with accepted wins and eligible-suite coverage.
Name the exact acceptance version. Then state the next actual-path return,
its blocker and ETA from observed phase/receipts. If any denominator or eligibility
is unknown, say `UNKNOWN` instead of filling it from a remembered plan.
