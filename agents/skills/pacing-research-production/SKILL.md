# pacing-research-production — 委任した研究・制作を速く回す規律

> 出自: 2026-07-22 のポストモーテム(依頼主の指摘「なぜここまで遅い」)。
> 同日の実測: 最初の計算が着手から約 2 時間遅れ・応答の約 2 割が文章検査による再送。
> 同日深夜の第2次ポストモーテム(速度の注意4回)で P7〜P9 を追加。実測: 判定に関わらない
> 走行を遅い装置に置いて2時間浪費・測定条件の不一致で比較実験を1周再走・補助変数の
> 連動を見落として判別実験が1回無効化。本 skill は分野の固有名を含めない ── どの領域の
> 委任作業にも適用する。各 gate は機械で確認できる artifact を要求する。

## LAW

> **検証は「公表を止める門」であって「生産を止める門」ではない。**
> 生産(計算・試作・起草)と検証(相談・照合・裏づけ)は並列に走らせる。
> 委任の往復は一巡ごとに機構で削る。前進の無い応答は作らない。

## Gates(P1〜P9・各行に artifact)

| Gate | 規則 | artifact |
|---|---|---|
| **P1 PROBE-FIRST** | 新しいテーマに着手した turn の内に、最小の具体的な計算または試作を 1 本走らせる。相談・調査の完了を待たない | 同 turn の実行出力(具体的な結果が出ていること) |
| **P2 CONCURRENT-VERIFY** | 相談・文献照合・裏づけ調査は背面(background / Workflow)で発射し、待ち時間に前面で生産物(定式化・試作・指示書)を進める | 同一 turn に「背面発射」と「前面生産」の両方が存在 |
| **P3 PRE-SEND FLOOR** | 長い報告(目安 10 行超)は、送信前にファイルへ書き、環境にある文章検査を自分で通す。検査が無い環境ではこの gate は省略する | 検査の通過出力 |
| **P4 ROUND-TRIP ECONOMY** | 査読担当への指示に「全指摘に修復経路を明示せよ」を必ず含める。二巡目以降の起草指示書には、前巡で繰り返された指摘の型を事前に焼き込む | 指示書内の該当文言 |
| **P5 NO-EMPTY-TURN** | 背面作業の完了待ちで、状態報告だけの応答を作らない。報告すべき前進が無ければ黙って待つ | 該当応答の不存在(運用点検) |
| **P6 VERIFY-NOT-TRUST** | 相談・文献に由来する載荷主張は、(a) 自前の計算、(b) 一次資料の本文、(c) 独立の再計算、のいずれかで確定するまで成果物に書かない。異なる担当・模型の間の不一致は、最初に引く糸として扱う | 成果物内で主張ごとに検証手段が名指しされている |
| **P7 DEVICE-BUDGET** | 結論を左右する計算は最速の資源で回す。遅い資源に置いてよいのは結論に関わらない記録用と、資源の制約がある計測だけで、発進時に理由と見積り時間を 1 行申告する。新しい計測は最小規模の試走で費用を実測してから本走する。同じ資源を要する自分の走行同士は直列に並べる(取り合いで全部を減速させない) | 発進時の理由+見積りの行/試走の出力 |
| **P8 FOOTING** | 数値の比較は、測定条件の全ての軸(評価データの取り方・乱数の種・反復回数・しきい値など)が一致した土俵でのみ行う。比較の前に条件の差分を確認し、成果物の比較表に土俵を脚注で明記する | 比較表の土俵の脚注/不一致を見つけた場合は再測の記録 |
| **P9 CONFOUND-TABLE** | 1 つの変数を動かす判別実験は、その変数が同時に動かしてしまう量の一覧(交絡の表)を先に書き、それを打ち消す正規化の腕を設計してから走らせる | 実験の実行体の冒頭にある交絡の表 |

## 標準 pipeline(順序が本体)

1. **着手 turn**: 最小の試作を走らせる(P1)。同時に、必要な検証(相談の panel・
   文献照合)を背面へ発射する(P2)。panel の指示書は枠組みを固定しない四問
   (攻撃・代替案・射程内で最も有望な一手・既知による先取り)で書き、
   出典つき主張と記憶頼み主張を区別させる。
2. **収束**: 返ってきた材料の不一致を、一次資料と自前の計算で裁定する(P6)。
3. **起草委任**: 起草担当へ自己完結の指示書を渡す。指示書には目標・根拠資料・
   数値や事実の錨・「証明や確認ができない箇所はごまかさず明記せよ」を含める。
   独立な起草は並列に発射する。
4. **査読**: 査読担当へ。修復経路の明示を要求する(P4)。生成者と査読者は分ける。
5. **検収**: 検収者が独立の再計算と環境の検査で確定し、正本へ置く。
   探索段階の数値を正式な成果へ昇格させるときは、再現可能な形へ移す。

## MUST-NOT-FIRE と fire/no-fire(desk-check 用)

FIRES: 「研究を進めて」「どんどん進めて/さっさとやれ(制作の文脈)」
「起草と査読を委任して」「複数の模型に相談して水平思考」
「定理・文書を起草・査読させて」「仕事が遅い/生産性/ポストモーテムの是正を適用」。

MUST NOT fire(route):

| ask | route |
|---|---|
| 個別 CLI の flag・model 指定・呼び出しの正しさ | `driving-codex` 等の driving-* 系 |
| 文献体系化の台帳・確度・矛盾調停の作法 | `systematizing-knowledge` |
| 次に何をやるべきかの選定・撤退判断 | `directing-research` |
| 文章規則の中身・語の登録 | `linting-prose` と環境の検査設定 |
| 対象分野の事実・位置づけの判断 | その分野の project skill |
| 一行の質問への即答 | skill 不要 |
