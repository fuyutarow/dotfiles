# Task A: 文書構造と有用性のレビュー（control）

## 結論

db を直接使う読者には `db-guide.md` と `architecture.md` が実用になる。技術的な答えを先頭に置き、回復の限界も書いている。読者への被害は次の三点に集まる。見出しの主張が後段の限定より強いこと、app 固有の規則が基盤文書に混ざること、回復の答えが複数節に散ること。

## 確認できた問題（抽出本文が根拠）

1. **見出しの主張と検証範囲が合わない。** `architecture.md` 3行目は「別のアプリも…db の機構を利用できます」と断定する。しかし `db-guide.md` 55–57行では、公開 Record と sealed Record の検査は localnet のみで、121行は「公開 testnet…は保証しません」と限定する。採用を判断する読者は冒頭だけで読み終えかねない。（保証の範囲）
2. **文書冒頭に bookkeeping がある。** `heritage-overview.md` 3–7行は、読者・文書の種類・確認基準・再編前の版 hash を製品目的より前に置く。同じ情報を `architecture.md` 79–81行は末尾に置いており、こちらが正しい配置である。（編集上の配置）
3. **現行規則が経緯に埋もれる。** `heritage-overview.md` 34行は「10/23の追加決定。原資料の『下書き』はこの決定により採らず…」と、現行規則（許可範囲を直接読み書きする）と決定の経緯を同じ段落に置く。現行規則を先に書き、経緯は `decisions.md` 側へ送るべきである。（編集記録と規範の混在）
4. **基盤文書に app の規約が混ざる。** `infrastructure.md` 15行（文化継承の二重保存）、37行（Google/Enoki と LiNK の費用負担）、39行（sponsor allowlist）は、db 利用者の判断には直接関係しない。読者が「Walrus と R2 の両方が必須」と誤読する余地がある。実装の選択（採用インフラ）と app の規約は分けるべきである。（実装選択と app 規約の混在）
5. **再起動後の回復の答えが四箇所に散る。** `db-guide.md` 87行、89行、98行、121行にそれぞれ「自動復元されない」「自動で閉鎖しない」「保証しない」が書かれている。読者が求める答え「`connect().submit` は再起動後に自動回復しない。app が保存と照合を組む」を、第5節の冒頭に一文で置くべきである。（保証の所在）
6. **`CommitExecutionUnknown` の扱いが例示表に依存する。** `db-guide.md` 77行の表見出しは「code の例」で、網羅かどうか書かれていない。「結果不明を失敗確定や再送可能へ変換しない」という規則は、表にない code にも及ぶのか読者には判定できない。（保証の範囲、未確定）

## 抽出では判定できないこと（欠陥とは断定しない）

- `narrow-reference.md` は Scope で setup を別の getting-started に委ね、対象を exact lookup に限っている。ここに client 初期化の例が無いことは欠陥ではない。
- ただし `NotFound` は「visible な receipt が無い」と書く。何に対して見えるか（資格・Policy）は書かれておらず、`payload` が復号済みか保護のままかも書かれていない。保護された record の暗号文をそのまま描画する誤用を、この抽出からは排除できない。確定には対象の API 参照（抽出外）を要する。
- `db.md`、S1〜S12、Q5、rule `one-transaction`、ROLE-01〜07、`decisions.md`、監査 ID（G12、A3）は抽出に含まれない。リンク先が不在であると断定しない。`db-guide.md` の手順番号は `db.md` なしには引けない。
- `site-index.md` は `/spec/...` の絶対経路、`spec-index.md` は相対ファイル経路を使う。二つのリンク規約が併存する。どちらが読者の実際の入口かは、サイト生成設定が無いため判定できない。

## 分類メモ

- 保証: 読み取った Node kind だけで認可を判断できない（`architecture.md` 33行）。外部保存の成功は参照の確定ではない（`architecture.md` 47行）。ChainAbort だけでは失敗確定しない（`db-guide.md` 108行）。
- 実装選択: 採用インフラ（`infrastructure.md`）、変換器・型生成器（`spec-index.md` 37行の参照先）。
- 編集記録: 10/23 決定、再編の経緯（`spec-index.md` 75–77行、`heritage-overview.md` 5行）。
