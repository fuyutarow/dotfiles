# Scientific loop — from anomaly to a discriminating candidate revision

Use for scientific diagnosis, Strong Inference or revision of a hypothesis, model, design or procedure.
This reference owns bounded test selection and the next action. Candidate genesis and proof certification stay upstream.
Its source map is below. Read the relevant soks position, ledger and evidence at their current source locators.
Retain source scope and uncertainty. Reuse unchanged bindings instead of repeating a literature review each cycle.

## 1. Fix the contrast before explaining it

Map the inspected observation path and what is observed, failing or unmeasured.
Separate established dependencies from hypothesized causal connections.
Separate the target system, isolated component, idealized construction, historical reference and formal model.
Bind the object/statement, conditions, sample/observation window, protocol and instrument validity.
State `observed P; expected Q from account/reference R under conditions A`.
If footing differs, repair the comparison or narrow the question before naming a cause.
Performance, correctness and requirement conformance are different explananda; one need not explain all three.

## 2. Form candidates, then compare them

Use the candidate owner for the needed operation; `references/skill-composition.md` gives the boundary.
Explain a raw contrast with `forming-hypotheses-from-anomalies`; transform sourced seeds with `forging-novel-theses`.
Apply these inline when possible, then consume the result without ending the authorized loop at a handoff.
Reuse an existing adequate rival set directly; generation is not a mandatory stage on every cycle.
For each candidate, name the mechanism, explained contrast, scope and facts it leaves unexplained.
Name supplied vocabulary/operators and the cheap existing explanation already checked.
Retrieve prior mechanisms before inventing one, but treat transfer as a current hypothesis, not achieved capability.
Include compatible combinations when causes can coexist; retain `OTHER/UNRESOLVED` without inventing its content.
Do not infer H1 from “H5 explains only part.” The residual is a new contrast, not proof of the favored candidate.
When the set fails to explain a result, reopen generation instead of continually repairing the favorite story.

## 3. Derive predictions that can change a decision

Write the rival-specific prediction under explicit auxiliaries, and ask what can happen if that hypothesis is false.
State exactly which pair/subclaim the check separates. A test need not uniquely identify every cause at once.
If all named rivals predict the same outcome, discard that prediction as their discriminator and find another witness.
For noisy observations, specify differing distributions/margins and an inconclusive region, not logical impossibility.
If hypothesis H and auxiliaries A imply P, not-P challenges the conjunction; inspect A before excluding H alone.
Name auxiliary failures: inactive intervention, changed task, binding, state or oracle mismatch.
Check realized interventions through the evidence owner; a flag or an attractive predicted score proves nothing.
Do not redefine the predictor, threshold or scope after seeing a miss; a repaired experiment gets a new binding.

## 4. Choose the cheapest decisive next observation

Prefer an existing trace, tiny counterexample, proof obligation or matched intervention over another large accuracy run.
Select by the changed decision and time to an interpretable return. Do not invent numerical information-gain scores.
Use one semantic change when causal attribution needs it. A combined repair establishes at most the tested bundle's effect.
Do not demand a full factorial sweep: choose the one extra arm that separates the current rival explanations.
A diagnostic using information unavailable at decision time is not itself a prospective rule.
It may witness an outcome under that extra information. Causal localization needs its own trace or intervention.
Selecting success with privileged outcome information proves neither an identifiable cause nor a usable prior rule.
Prewrite outcomes, excluded subclaims, surviving candidates, auxiliary checks and the next branch.
Keep unchanged controls/context by locator. Scope safety and admission still apply.
Independent questions may run broadly in parallel; result-dependent successors wait only for their own needed result.

## 5. Learn locally, revise the candidate immediately

| Observation | Update now | Do not conclude |
|---|---|---|
| Two measurement paths agree in one bound condition | Reject the tested discrepancy there; retain common errors and untested conditions | Every result is valid or shared errors are impossible |
| More observations change an aggregate estimate but a discrepancy remains | Retain scoped observations; infer an effect only under the frozen uncertainty criterion | The remaining discrepancy must be H1 |
| A two-factor intervention improves a model or prototype | Preserve the bundle's scoped effect; isolate a factor only if the next decision needs it | Either factor is uniquely causal or field performance is established |
| One population or operating condition contradicts an explanation | Revise that hypothesis's scope and affected work now | The hypothesis is globally false or all other conditions are explained |
| A supplied idealization or hand-selected construction succeeds | A scoped constructive witness exists | A tight bound or the target system's own attainable performance is proved |
| A different construction succeeds for each case | Keep the constructions and assumptions separate | One uniform model, design or procedure succeeds across all cases |
| No proposed row predicts what occurred | Check instrument/auxiliaries; reopen candidates when needed | Choose the least-bad candidate as established truth |

Return a candidate revision, not a promise to “integrate all fixes”:

```text
retain -> minimal changed assumption/mechanism/interface -> supported scope -> predicted contrast -> first target check
```

Pin the predecessor and new candidate versions. Preserve every disproved prediction and unresolved obligation.
Name the information available when each revised decision must be made.
Replace privileged diagnostic choices with a prospective rule before claiming attainable target behavior.
Name the rule, not just a function signature. If the rule is unknown, return that open generation problem explicitly.
Test that rule on the actual target path; do not report the diagnostic's result as the revised target's achievement.
The first return remains a microticket. Do not bury the next discriminator inside a forty-minute integration job.
Send scoped findings to theory/evidence owners and cancel or revise affected work without a fleet-wide barrier.
