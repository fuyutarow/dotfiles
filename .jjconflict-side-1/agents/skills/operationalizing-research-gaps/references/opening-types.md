# Opening types — what may become a row, and what each type may claim

> **SOLE owner** of the admission test for an `OPENING`, the four row types, the reason classes, the
> per-type evidential license, and the `UNTESTABLE-AS-STATED` disposal. It does NOT own the gap
> typology: `systematizing-knowledge` `references/delivery.md` §5 is the sole home of the seven gap
> kinds (coverage / evidence / inconsistency / comparability / construct-theory / method / translation).
> Read that there. This file adds only the two things it does not carry — why the hole is still there,
> and what shape of work would close it.

## 1. Admission — is this an opening at all?

Four tests, all required:

1. **Traceable.** It resolves to a locus in the signed position — a claim row, a gap row, a
   discrepancy, an excluded-source note, or a `DONOR SET` record. An item with no anchor is not an
   opening; it is a new question, and it belongs to whoever owns the corpus.
2. **Inside the coverage contract.** An opening inherits the position's boundary. If answering it
   requires sources the contract excluded, the honest row is a coverage-widening request addressed to
   `systematizing-knowledge`, not an opening.
3. **Unselected.** Nobody has committed to it, allocated to it, or paid for it. The moment one is
   selected and about to be paid for, it leaves this skill (→ `acting-on-hypotheses`).
4. **Retirable.** Some observation would settle it (`references/test-and-referee.md`). If none can be
   named, dispose of it under §4 below.

## 2. The four row types

The type answers **what shape of work retires this row**. It is orthogonal to the SoK's gap kind: a
single `evidence gap` may become a `GAP` row for one project and a `TASK` row for another, depending
on whether a referee can be written.

### `GAP` — a missing observation inside the declared scope

| Field | Contract |
|---|---|
| Admission | The position states that something is not established, and the reason is a missing measurement, derivation, or source — not a disagreement between sources |
| Required cells | anchor · reason class · `RETIRED-BY` · addressee · `EXPIRES` |
| Licensed claim | "Within `<coverage>`, no admitted source establishes X, and observation O would settle it." |
| Forbidden | Asserting not-X. A gap is the absence of support, never support for the negation |

### `CONTRADICTION` — a live disagreement carried forward on purpose

| Field | Contract |
|---|---|
| Admission | Two or more admitted sources are materially discrepant and the position recorded the discrepancy as `unresolved` or `not-comparable` |
| Required cells | anchor to **both** loci · reason class · `RETIRED-BY` (the observation that discriminates between them) · addressee · `EXPIRES` |
| Licensed claim | "Sources A and B disagree on X under conditions C; observation O distinguishes them." |
| Forbidden | Choosing a side, averaging, inventing a moderator, or collapsing the row into one verdict line. Curation's measured cost is exactly the suppression of a subdomain's conflicts (`GENERATIVE-SOK.md` §G2), so this row type exists to resist the smoothing pressure, not to be resolved by prose |

A `CONTRADICTION` whose discrepancy turns out to be a comparability artifact is not retired here — it
goes back to the corpus owner, because re-adjudicating comparability changes the position.

### `NON-ADJACENCY` — two bodies that share a mechanism and have never met

| Field | Contract |
|---|---|
| Admission | Two admitted sources (or two SoK themes) name the same mechanism, quantity, or failure condition, and neither cites the other nor any common bridge |
| Required cells | both anchors · the shared mechanism as *named in each source's own words* · `RETIRED-BY` · addressee · `EXPIRES` |
| Licensed claim | "Source A and source B both constrain M, and no admitted source connects them; observation O would show whether the connection holds." |
| Forbidden | Stating, predicting, or hinting at a relation between them. **No `RELATION:` cell is permitted on this row type** — the floor script enforces this mechanically. The moment a correspondence is asserted, the work has become a transfer thesis and belongs to `forging-novel-theses` |

Why the restraint: the discovery tradition built on this structure (literature-based discovery) has
acknowledged reproducibility and evaluation problems and no established prospective record
(`GENERATIVE-SOK.md` §G5). The *structure* is admissible as a place to look. The *relation* is not a
finding this skill may produce.

Shared vocabulary is not a shared mechanism. Two sources both using "exact", "stable", or "bounded"
are a retrieval cue, not a non-adjacency — the same over-admission trap the `DONOR SET` records.

### `TASK` — an opening with a referee attached

| Field | Contract |
|---|---|
| Admission | Someone else's output could be scored against a fixed criterion without consulting the author (`references/test-and-referee.md` §3) |
| Required cells | anchor · reason class · `REFEREE` · fixed threshold · `RETIRED-BY` · addressee · `EXPIRES` |
| Licensed claim | "Here is the input, here is what counts as a pass, here is who scores it." |
| Forbidden | Claiming the task form accelerates anything. Its support is one essay's stated position plus one architectural convergence (`GENERATIVE-SOK.md` §G8), and that is not a measurement |

`TASK` is the strongest row type available and every other type is checked against promotion to it at
step 4 of the procedure.

## 3. Reason class — why the hole is still there

Assign exactly one. The reason selects the action; a row typed only by subject selects nothing.

| Reason class | The position's evidence looks like | Action the row licenses |
|---|---|---|
| `INSUFFICIENT` | no admitted source, or too imprecise to discriminate | take the measurement or derivation |
| `INCONSISTENT` | admitted sources materially disagree, consistency unknown | run the discriminating observation |
| `BIASED` | the available evidence shares a design or source-side limitation | replicate under a design that does not share it |
| `WRONG-QUESTION` | the literature answers a neighbouring question, not this one | reformulate; this row's retirement is a better-posed question, not data |

Adapted from the AHRQ research-gap framework (Robinson, Saldanha & McKoy 2011 — verification class
`SECONDARY-SUMMARY`; see `references/sources.md`). A `WRONG-QUESTION` row is the one whose retiring
observation is allowed to be a document rather than a measurement.

## 4. Disposal — `UNTESTABLE-AS-STATED`

A candidate with no nameable retiring observation is not shipped as prose. Choose one:

| Disposal | When | Where it goes |
|---|---|---|
| Reformulate | the question is real but posed at the wrong grain | re-enter at §1 as a `WRONG-QUESTION` row whose retirement is the better-posed question |
| Return to the corpus owner | it needs the position re-adjudicated, or the coverage widened | `systematizing-knowledge` |
| Route as a passive update condition | it waits on the world (a paywall lifting, a source becoming reachable, someone else publishing) | `systematizing-knowledge` `references/delivery.md` §9 living-update procedure — a world-condition is a legitimate update trigger and is **never** an opening, because no one here can act on it |
| Drop | it neither anchors nor retires | say so in the sheet's disposal list; silent dropping hides the burial |

The third row is the corpus's observed failure mode, not a hypothetical: the `soks/` update conditions
are world-conditions in the place where openings should be (`GENERATIVE-SOK.md` §G6).
