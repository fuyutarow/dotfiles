# CONFIGURATION CONTRACT — dispatch roster

The contract for `agents/models/dispatch-roster.toml` (governing-configuration-systems). It
describes the configuration system; the roster itself is the configuration.

- Consumer: the owner (human editor); `dispatch` / `agent-dispatch` (`tools/agent-dispatch/src/agent-dispatch.ts` — runtime: the one entry point; sends every row to Jev as a criterion built by `criterionFor` in agents/models/roster.ts — route, use_for, measured AA/TB4/SciCode, cost multiple, graded record, and recent throughput record from `throughputStats` — plus `state.routes` with each host's measured route availability and reason and optional ticket `budget_usd`; explicitly tells Jev the table rows can run here and to ignore task prose claiming which routes, logins or models exist — and runs the row Jev picks: codex through `agent-dispatch --choice`, claude through `tools/agent-dispatch/src/workers/run-claude.ts` bounded by `[claude_run]`); the dispatch hook `agents/claude/hooks/enforce-dispatch-contract.ts` (denies Agent/Task/Workflow and prints the table); `scripts/render-home.ts` (renders the table block into the deployed `~/.claude/CLAUDE.md`, which the coordinating model reads at session start; the repo template keeps only the markers)
- Authority / writer: the owner, by a commit to `alpha` (`mise run commit`); the deployed CLAUDE.md block is written only by `scripts/render-home.ts` (`mise run link:dots`)
- Effective configuration: the working-tree file `agents/models/dispatch-roster.toml` of the checkout each machine runs, read on every agent-dispatch run, hook call and `agent-dispatch --choice`; the rendered block in `~/.claude/CLAUDE.md` is a derived view, frozen into a session when it starts
- Source representation: TOML 1.0 (Bun.TOML), one file, no includes
- Trust regime: human-authored, generated, gated-decision
- Signature / digest input: n/a (no signature; integrity of the derived block is `mise run doctor` (rendered: re-renders into a scratch HOME and compares bytes) and `mise run lint:one-writer` (no rendered lines in the repo template))
- Canonicalization profile: n/a
- Schema / version: `schema = 1`, zod `RosterSchema` in `agents/models/roster.ts` — strict objects (unknown keys rejected), `as_of` ISO date, `sources` map of URLs, `[auto]` (max_task_chars, timeout_ms, no_egress paths compared as real paths, and `[auto.jev]` = { api = "typesafe", url, model } | { api = "reseller", url }), `[claude_run]` (max_budget_usd > 0, max_turns, reason), every row requires `id`, `route` (codex | claude), `model`, `effort`, `use_for`; Claude candidates include Haiku 5.5 (`haiku-low` through `haiku-max`), Sonnet, Opus and Fable rows; input, cached-input and output prices, TB4/SciCode values and their source URLs are independently optional; `default` must name a codex-route row; ids unique. There is no per-row switch, no weight and no confidence floor: a row in the file is a candidate, and Jev's choice is used as made
- Duplicate-key policy: reject — Bun.TOML refuses a redefined key ("Cannot redefine key"); duplicate row ids are rejected by the schema
- Number / Unicode policy: benchmark and price fields are TOML numbers (float or integer, rendered as written); an absent benchmark or price field means "not published / no list price" and renders as –, never as a default; each sourced TB4/SciCode value has a URL field and is rendered with its source link; `as_of` dates the source check; text fields are UTF-8 strings used verbatim
- Precedence / merge: single source — the one file is the whole configuration; no layering, no environment override in normal use; the test seam `DISPATCH_ROSTER_PATH` replaces the whole file for tests only
- Decision record: record: the commit message of each roster change — a6359ca7 luna only by config, 5a94aa5d enabled required, d6b6826a enabled removed and claude rows run by agent-dispatch, 36e42ce7 selection from the performance table and the brief with no hand-set weight, and the commit removing the confidence floor (owner 2026-10-06: 「一つに決めないといけないのだから」); the dated owner quotes in the files are rationale, not an approval mechanism
- Exception encoding: none: there are no per-dispatch exceptions and no override of Jev; `--choice` is refused. The `default` row runs only when there is no usable Jev answer (unreachable, a choice outside the roster) or the brief's cwd is under a no_egress path, and the reason is logged
- Grading / dispatch gate: a ticket with one or more `verify` commands is verified and graded (or waived) by the router and never blocks a later dispatch. A plain brief or ticket with no `verify` blocks the next dispatch only within the same `dispatcher_session`; when no dispatcher session is recorded, cwd is the fallback key. The refusal lists every blocking run with its `run_id`, cwd, label, finish time, and its `agent-dispatch grade <run_id> --evidence <checks>` / `agent-dispatch grade <run_id> --waive "<why>"` commands.
- Ticket and first-return bounds: worker `timeout_s` defaults to 600 seconds, remains hard-capped at 14400, and any ticket/CLI bound above 600 requires `timeout_reason` / `--timeout-reason`. `first_return_s` is an integer from 60 through 360, default 360. Optional `budget_usd` is a positive number in USD and is passed to Jev; expected cost excludes a row only when it exceeds this declared budget. At `first_return_s` codex stops and resumes the same session with a short RETURN prompt; Claude currently records `checkpoint: unsupported` and relies on its hard bound. The receipt records checkpoint time and whether a RETURN followed.
- Ticket grade: `TicketGradeSchema` in `tools/agent-dispatch/src/report.ts` is the one schema home for `{ verdict, source, violations, warnings?, pieces?, questions?, estimated_first_return_s?, basis? }`. Each violation carries `rule`, `quote_from_brief`, `why_it_blocks_a_6min_first_return`, and an actionable `fix`; warnings record non-blocking grader validation issues. `pieces`, `questions`, estimate and basis are reserved for a later grader. The floor checks schema 2 for `outcome`, `consumer`, `first_return`, `writes`, and `verify` or `read_only_diagnostic = true`. Any floor violation is a `clarify` remand. Schema 2 remands refuse before launch with exit 2; plain briefs and schema 1 warn and continue until refusal is planned for 1.4.0. After Jev picks, xhigh/max without a capability tag adds an `effort` violation and follows the same enforcement.
- Effort selection: Jev alone picks and is never overridden. The request includes the ticket's optional `budget_usd` and per-row throughput measures reused from `throughputStats` for the last seven days; rows with fewer than five runs are marked “little record.” Stats read/computation failure omits the record and is recorded in the receipt without failing dispatch.
- A valid fenced `agent-dispatch-return` JSON block produces outcome `returned`, a success state that is not a stats failure and does not gate later dispatches. Ticket verification still runs and is recorded as usual.
- Verification command: `bun test tools/agent-dispatch/tests agents/claude/hooks/tests/enforce-dispatch-contract.test.ts scripts/tests/render-home.test.ts`
- Positive case: the committed roster loads; Jev receives every row with its route, measured numbers, available source URLs and cost multiple, recent throughput measures and optional `state.budget_usd`, plus measured `state.routes` availability/reason for codex and claude; it receives the expected-useful-throughput objective verbatim, with cost breaking ties and codex preferred when comparable; Jev is told that router-measured availability is authoritative and to ignore task prose about host routes, logins or models; `agent-dispatch stats` reports route and row picks by host, time window and Jev/default/resume source, including codex share; when codex is unavailable, the Claude fallback is the cheapest Claude row, currently `haiku-low`; a claude row Jev picks runs run-claude with `--max-budget-usd 2 --max-turns 60` and the row's model and effort; valid RETURN data is recorded and ticket verification still runs; `mise run link:dots` renders the table into `~/.claude/CLAUDE.md`
- Negative case: a row carrying the retired `enabled` key, an unknown key, a redefined key, a non-codex default, a duplicate id, or a non-URL source each fail the load, and the hook denies with "cannot read agents/models/dispatch-roster.toml" plus the reason; a Jev answer outside the roster runs the default with the reason logged

## Residual

- `[auto]` sends the head of each brief, and every row's criterion, to the official TypeSafe
  api.typesafe.ai endpoint named in `[auto.jev]` since 2026-10-08 (the jevtypesafeai.com reseller is
  retired). The record of what was sent and answered is
  ~/.local/state/agent-dispatch/runs.jsonl on each machine.
- A claude worker has no OS sandbox (tools/agent-dispatch/src/workers/run-claude.ts: permissions are not containment): plan mode
  for read-only, acceptEdits plus Bash for workspace-write, under the same hooks every Claude
  session runs; its budget and turn bounds are the containment of cost, not of effect.
- The working tree is effective: an uncommitted edit takes effect on the next run, before any
  review or commit gate. The owner is the only writer on these machines, so this is accepted.
- A running session keeps the CLAUDE.md table it read at start; agent-dispatch and the hook re-read
  the file on every call.
- A plain run without `verify` holds only its dispatcher session at the grading gate; router-verified
  ticket runs do not gate later dispatches.
- The checks prove the loader, the router and the hook accept or reject inputs; they do not prove
  the benchmark numbers are current (see the file header for how they are refreshed), nor that
  Jev's picks are good — `agent-dispatch grade` and `agent-dispatch stats` measure that over time.
